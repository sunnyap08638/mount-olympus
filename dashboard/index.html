FIELD GUIDE

How it works

Follow a reading or an action from the page to the hardware.

Follow the data

The browser, dashboard server and local runtimes each have a role.

01

Collect on Ubuntu

collect.py samples Linux CPU counters, memory and mount capacity. It uses docker stats for Docker and reads Mneme’s container cgroup for CPU and RAM.

02

Serve a JSON snapshot

server.py caches runtime samples every eight seconds. A separate five-minute scan measures allocated disk space without making every page refresh walk the disks.

03

Render in the browser

dashboard.js fetches /api/snapshot and updates the cards. Open DevTools → Network and click the request to inspect the numbers feeding the UI.

04

Send a bounded action

A confirmed click sends a service ID and action to /api/action. The server checks a fixed list and delegates to Docker Compose or the scoped K3s helper. The next sample shows what happened.

Gaming PC and Raspberry Pi

How these pieces fit into the network.

Windows and Linux boot

Use Windows for games and Linux for Ollama and other compute jobs. A separate SSD keeps the installations easier to manage. Wake-on-LAN uses the configured boot target, so set Linux first if jobs should run unattended.

Remote Windows desktop

Sunshine streams Windows to Moonlight with keyboard, mouse and controller input. Test locally before connecting over Tailscale. The gaming PC needs to be booted into Windows for this connection.

Raspberry Pi and Pi-hole

The Fios router forwards DNS to Pi-hole on the Pi. The Overview card checks whether Ubuntu can resolve a domain through Pi-hole and reach its admin page.
